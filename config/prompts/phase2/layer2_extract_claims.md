从以下硬件设计文档中提取所有**可被 RTL 实现验证的设计声明**。

每条声明必须是精确的、可独立验证的断言，格式固定为：
{
  "claim": "一句完整的设计声明",
  "source": "文档章节名",
  "signals": ["涉及的信号名（从文档推断，3-5个）"],
  "keywords": ["检索关键词（5-8个中英文）"],
  "scope": "模块名或空"
}

**必须覆盖以下所有类别（每个类别至少提取 1 条）**：
1. 功能模式：支持哪些操作模式、算法、配置
2. 状态/生命周期：初始化、启动、清除、空闲、完成的条件和顺序
3. 安全/清除：密钥、状态、寄存器在何时以何种方式被清除/擦除
4. 数据路径：关键数据如何流动、选择、转换
5. 时序/延迟：操作的延迟、流水线阶段、等待条件
6. 错误/故障处理：错误如何检测、如何报告、如何恢复

**特别注意安全相关声明**（擦除/清除/伪随机/密钥生命周期/故障检测），这些是 RTL bug 最常出现的地方。
文档中的 Clearing Registers / De-Initialization / Pseudo-Random Data 章节通常包含高价值声明。

**严禁**：编造文档中没有的声明、写泛泛的"系统应正确工作"、遗漏安全清除相关章节。

输出格式（必须是合法 JSON，不要输出任何其他内容）：
{"claims": [{"claim": "...", "source": "...", "signals": [...], "keywords": [...], "scope": "..."}]}
