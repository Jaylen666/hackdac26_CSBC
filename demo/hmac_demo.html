Step 2: LLM-Generated Structured Specs

C2 assign_sha_message_length Spec

Summary: 根据 HMAC 使能状态、消息长度选择阶段和摘要算法类型，组合计算送往 SHA 的消息比特长度。

Guarantee 0: 当 hmac_en_i=0 时，sha_msg_len = message_length_i。

Guarantee 1: 当 hmac_en_i=1 且 sel_msglen == SelIPadMsg 时，SHA2_256 使用 512-bit block size，SHA2_384/SHA2_512 使用 1024-bit block size。

Guarantee 2: 当 hmac_en_i=1 且 sel_msglen != SelIPadMsg 时，SHA2_256 → +256，SHA2_384 → +384，other/default → +384。

Assumption: 在 HMAC 最终哈希路径中，digest_size_i 应只取该实现支持的合法编码；若期望 SHA2_512 语义，需要确认其不会依赖 default 的 384-bit 回退。

Uncertain Point: 最终哈希长度计算中，SHA2_512 没有显式分支；default 返回 BlockSizeSHA512in64 + 384。这是否有意将 SHA2_512 与 SHA2_384 共享 384-bit 中间摘要长度，还是遗漏 512-bit 分支，需要结合上下文确认。

C1 cast_digest_size Spec

Guarantee: 当 digest_size_supplied 为 SHA2_256、SHA2_384 或 SHA2_512 时，digest_size 一定分别输出对应合法枚举值。

Why it matters: 该 guarantee 告诉下游 HMAC core，SHA2_512 是合法支持模式，不是应落入 defensive default 的非法值。

Step 5: Channel B LLM Mismatch Analysis

Output file: output/findings_hmac_curated_top10.json. Channel B reads each selected AG/U work item and writes one finding entry per suspicious mismatch into finding.json-style output.

F-0025 verdict=GAP, severity=HIGH, score=0.63. The LLM identifies that the final HMAC path only handles SHA2_256 and SHA2_384; other encodings fall back to BlockSizeSHA512in64 + 384. If SHA2_512 is legal, this is missing legal-mode coverage rather than a defensive default.

Evidence stored in finding.json: assumption says final SHA2_512 semantics must not rely on the 384-bit fallback; guarantee says the outer path maps SHA2_256 to +256, SHA2_384 to +384, and other/default to +384.

Important: Channel B does not yet prove the RTL bug. It marks a candidate mismatch for Phase3/Codex source-level verification.

Step 6: Phase3 Codex Source Confirmation

Input: Channel B finding F-0025 plus related RTL/spec context. Codex then checks source instead of trusting the pair-level mismatch alone.

Final bug candidate: hmac_bug_003, status proven in diff_bug_convergence/hmac/hmac_bug_003/proof_result_v1.json.

Codex confirmation: SHA2_512 is explicitly supported, but the final outer HMAC length computation collapses SHA2_512 to the SHA2_384 constant. Directed RTL proof observes SHA2_512 outer-round length as 1408 instead of expected 1536, and the software-visible witness reports a fully mismatched HMAC-SHA512 tag.

Observed witness: SHA384 control passes on the same platform; SHA512 reports mismatches=16, with actual digest words differing from the expected known-answer vector.
